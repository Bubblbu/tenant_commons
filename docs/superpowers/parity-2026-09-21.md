## Differences to look at

None — every mechanically comparable number matched exactly between the two builds (marker count, all four row counts). The only large deltas are expected/inherent, not parity bugs:

- **`index.html` bytes / total transfer**: Folium's `www/index.html` bakes ~5,281 markers as inline HTML/JS (23.2 MB, 4.51 MB gz); Vite's `dist/index.html` (18.3 KB) plus its JSON artifacts and JS bundle total 2.07 MB gz — this is the expected win from moving markers to JSON + client-side Leaflet rather than a parity problem.
- **`dataset_totals.buildings` (5,128) vs marker count (5,281)**: not a folium/vite discrepancy (both builds read the same export). The 153 are the `overlay_housing` records — 117 SROs and 36 co-ops whose address matched no building. They are drawn as markers and get table rows, but are excluded from building totals by design (they carry no units, value or membership data). The status bar should read 5,128 buildings in both builds.
